# SmartFleet - Development Instructions

## Project
SmartFleet Vehicle Usage Web Application
Baseline: v3.8.5

## Rules
1. Read docs/ROADMAP.md, docs/ARCHITECTURE.md, docs/PROGRESS.md and docs/TEST_PLAN.md before development.
2. Inspect existing source code before implementing features.
3. Reuse existing functions and components.
4. Never modify Production without explicit approval.
5. Work on a separate development branch.
6. Never commit secrets, credentials or .env files.
7. Use a separate Staging database for testing.
8. Preserve all existing vehicle usage and odometer records.
9. Run available build, lint and automated tests.
10. Update docs/PROGRESS.md after each batch.
11. Summarize changes, test results and outstanding issues.
12. Request approval before deployment or destructive migrations.

## Development Roadmap
- v3.8.6: Security and Automatic Backup
- v3.9.0: Mobile UX/UI
- v4.0.0: Dashboard and Reports
- v4.1.0: User and Permission Management
- v4.2.0: Multi-Vehicle Management

## Current Priority
Verify existing Backup and Vehicle Maintenance features before implementing new functionality.
