# SmartFleet Development Instructions

## Project
SmartFleet Vehicle Usage Web Application
Baseline version: v3.8.5

## Development Rules
1. Read docs/ROADMAP.md, docs/ARCHITECTURE.md, docs/PROGRESS.md and docs/TEST_PLAN.md before making changes.
2. Inspect the existing source code before implementing features.
3. Reuse existing components and avoid duplicate functionality.
4. Never modify production data or deploy to production without explicit approval.
5. Work on a separate development branch.
6. Never commit credentials, API secrets, or .env files.
7. Use a separate staging database for migrations and testing.
8. Preserve existing vehicle usage records and odometer history.
9. Run available build, lint and test commands after changes.
10. Update docs/PROGRESS.md after each completed batch.
11. Provide a concise summary of changed files, test results, risks and remaining work.
12. Stop and request approval before destructive migrations or production deployment.
