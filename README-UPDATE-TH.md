# Smart Fleet v3.9.0 — ดูแลรถยนต์และสำรองข้อมูลอัตโนมัติ

ฐานโค้ด: main fee38fc5a61f574da401fc7ceda9f07408f63173 (v3.8.5)

## เมนูดูแลรถยนต์

- พนักงานและ Admin ดูเตือนบำรุงรักษา/วันหมดอายุได้ ผ่านเมนูด้านข้างหรือปุ่มดูแลรถบนมือถือ
- Admin เพิ่ม แก้ไข ปิดรายการ และบันทึกดำเนินการแล้วพร้อมรอบถัดไปได้
- ระบุวันครบกำหนดหรือเลขไมล์อย่างน้อยหนึ่งอย่าง ถ้าระบุทั้งคู่ จะเตือนเมื่ออย่างใดอย่างหนึ่งถึงเกณฑ์
- ตั้งช่วงเตือนล่วงหน้าได้ สถานะปกติ ใกล้ครบกำหนด ครบกำหนด และเกินกำหนด ใช้เวลาไทย
- เลขไมล์อ้างอิงจากการคืนรถล่าสุด รายการบริการไม่เปลี่ยนเลขไมล์ของประวัติการเดินทาง
- ไม่สร้างวันหมดอายุ/รอบบริการสมมติลงฐานจริง ให้ Admin กรอกข้อมูลของบริษัท
- เตือนภายในเว็บเมื่อเปิดหรือรีเฟรชหน้า ยังไม่มีอีเมล LINE หรือ push notification
- ประวัติบริการ/หมายเหตุสำหรับ Admin เท่านั้น จำกัดรายการเตือน 200 รายการ และประวัติบริการ 1,000 รายการตามขอบเขตฐาน JSON เดิม

## สำรองอัตโนมัติ

จัดการข้อมูล → สำรองอัตโนมัติ (Admin เท่านั้น)

- ตั้ง Cloudflare Cron `0 19 * * *` = ทุกวัน 02:00 น. Asia/Bangkok ทำงานโดยไม่ต้องมีผู้เปิดเว็บ
- ฐานสำรองแยก: smart-fleet-demo-backups / smart-fleet-production-backups ใช้ binding DEMO_BACKUP_DB / BACKUP_DB ตามฝั่ง
- สร้างสำเนาก่อน Deploy ครั้งแรกผ่าน Workflow; schema-backup.sql ใช้เฉพาะฐานสำรอง ไม่ต้องรัน schema หลักซ้ำ
- เก็บวันละหนึ่งชุดย้อนหลังเจ็ดวันตามปฏิทินไทย กดสำรองซ้ำในวันเดียวกันจะอัปเดตชุดของวันนี้
- ตัดสำเนาเก่าหลังเขียนชุดใหม่สำเร็จเท่านั้น คงชุดเดิมหากเขียนชุดใหม่ล้มเหลว
- เปิด/ปิดตามเวลา สำรองทันที รีเฟรชสถานะ และดาวน์โหลด JSON/SQL จากชุดเดียวกันได้
- JSON มี SHA-256 ตรวจความครบถ้วน SQL กู้คืนข้อมูล บัญชี และรายการดูแลรถ โดยเปลี่ยน session key ให้เข้าสู่ระบบใหม่
- หน้า Admin แจ้งเมื่อสำรองล้มเหลว หรือไม่มีสำเนาสำเร็จใหม่เกิน 26 ชั่วโมง ไม่แสดงผลสำเร็จล่วงหน้า
- ไฟล์เป็นข้อมูลส่วนตัว รวมบัญชีและค่าแฮชรหัสผ่าน ไม่บันทึกลง GitHub หรือ job logs
- สำเนาแยกฐานแต่ยังอยู่บัญชี Cloudflare เดียวกัน ควรดาวน์โหลดเก็บนอกระบบเป็นระยะ
- ไม่มีภาพแนบ รอบนี้ไม่เพิ่มบัตรเครดิตหรือเปลี่ยนแผนบริการ หากสิทธิ์ D1 หรือโควตาไม่พอ Workflow จะหยุดก่อน Deploy

## Deploy

ใช้ Workflow Deploy Smart Fleet เลือก demo ก่อน เมื่อผ่านจึงเลือก production
ขั้น Prepare separate backups and save checkpoint ต้องใช้ Token ที่อ่าน/เขียน D1 ได้ นอกเหนือจากสิทธิ์ Workers เดิม
ขั้นตอนนี้อ่านข้อมูลหลักด้วย SELECT เท่านั้น และเขียนสำเนาไปฐานสำรองแยก ห้ามรัน schema-demo.sql หรือ schema-production.sql ทับฐานที่มีข้อมูล
ห้ามนำข้อมูลจำลองจาก .qa/ ไปใช้งานจริง
Cron ใหม่อาจใช้เวลาถึง 15 นาทีในการกระจายการตั้งค่าของ Cloudflare การ Deploy สำเร็จไม่ใช่หลักฐานว่ารอบ Cron ตามเวลาครั้งแรกทำงานแล้ว ให้ตรวจสถานะในหน้าสำรองหลัง 02:00 น.

## ผลทดสอบก่อน Deploy

Build Demo/Production, TypeScript และชุดทดสอบ 14 ชุดผ่าน
ทดสอบบันทึกรายการเตือน วัน/เลขไมล์ การปิด/ตั้งรอบใหม่ สิทธิ์พนักงาน CAS ข้อมูลชนกัน และการไม่เปลี่ยนเลขไมล์การเดินทาง
ทดสอบ scheduled handler จริงกับ SQLite แยกในหน่วยความจำ: เปิด/ปิดงานสำรอง หมุนเวียนเจ็ดวัน ปฏิเสธฐานผิดฝั่ง ป้องกันไฟล์แก้ไข บันทึกข้อผิดพลาดเมื่อเขียนไม่สำเร็จ และกู้คืน SQL รวมข้อมูลดูแลรถและบัญชีได้
ทดสอบ provisioning ด้วย API จำลอง: สร้างฐานแยกครั้งเดียว ใช้ซ้ำเมื่อรันใหม่ ตรวจ marker ป้องกันฐานผิด และหยุดเมื่อ API ปฏิเสธสิทธิ์
ตรวจ UI ผ่านเบราว์เซอร์มือถือกรอบ 390px (พื้นที่เนื้อหา 375px หลัง scrollbar) ไม่มีเนื้อหาล้นแนวนอน ตรวจหน้าวันหมดอายุ ฟอร์มเพิ่มเตือน และหน้าสำรองพร้อมสวิตช์
ไม่ได้สร้างรายการดูแลรถสมมติลง Production
